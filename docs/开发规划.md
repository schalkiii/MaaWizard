# MaaWizard 开发规划文档

> 基于 MaaFramework 的「可视化录制 + 节点编辑 + 一键真机运行」通用自动化 GUI
> 版本：v0.1（规划稿） ｜ 更新：2026-08-28

---

## 1. 背景与目标

### 1.1 调研结论（空白点）

通过对 MaaFramework 生态的调研，现有工具的能力分布如下：

| 工具 | 可视化编辑 | 直接运行 | 形态 | 面向人群 |
| ------ | ----------- | --------- | ------ | --------- |
| MaaInspector | ✅ vue-flow 节点编辑 | ✅ 内置运行/调试 | Tauri 桌面（仅 Windows） | 开发者 |
| MaaPipelineEditor | ✅ 拖拽工作流编辑 | 🔶 需 LocalBridge 桥接 | Web | 开发者 |
| MFAAvalonia / MXU / MFW-CFA / MWU | ❌ | ✅ 运行预置资源包 | 通用 GUI 运行器 | 终端用户 |
| KeymouseGo 等按键精灵类 | 录制后简单编辑 | ✅ 坐标录制回放 | 独立宏工具 | 大众 |

**核心空白**：不存在「大众向、录制即用、且基于 Maa 图像识别抗变」的 GUI。即没有「打开就能录屏 → 框选目标 → 自动生成识别节点 → 一键在手机/PC 上跑」的 Maa 版按键精灵。

### 1.2 项目目标

构建一个零代码、面向非开发者的自动化工具，组合：

- **按键精灵的易用性**：录屏即生成流程，无需手写 JSON。
- **Maa 的图像识别抗变性**：用 OCR/模板匹配替代固定坐标，抗分辨率/UI 位置变化。
- **双端一键运行**：Android（ADB）与 Windows（Win32）开箱即用。

## 2. 技术选型与 Rust 可行性论证

### 2.1 为什么选 Rust —— 已验证，且官方支持

1. **官方 Rust 绑定 `maa-framework-rs`**
   - 仓库：`github.com/MaaXYZ/maa-framework-rs`
   - 用法：`maa-framework = { version = "1", features = ["dynamic"] }`
   - 运行时加载预编译库：`maa_framework::load_library(std::path::Path::new("path/to/MaaFramework.dll"))`
   - 提供 Resource / Controller / Tasker 等一等公民 Rust API，无需手写 `bindgen`。

2. **GUI 框架 Tauri 2（Rust 后端 + Web 前端）**
   - 节点编辑器用 **Vue 3 + Vue Flow**（Web 前端），由 Tauri WebView 渲染。
   - **关键佐证**：MaaInspector 已采用「Tauri(Rust) + Vue3 + vue-flow」同栈，证明该组合可稳定驱动 MaaFramework + 图编辑器。
   - 后端用 Rust 封装 `maa-framework-rs`、设备管理与录制器，UI 与逻辑解耦。

3. **Rust 生态可直接支撑录制层**
   - 屏幕捕获：`scrap` / `screen-capture` crate（跨平台）；Win32 亦可走 `windows` crate。
   - 输入事件监听：`inputbot`（全局键鼠事件钩子）。
   - 输入模拟：录制期仅监听（`inputbot`）与截屏（`scrap`）；**实际执行由 MaaFramework Controller 完成，无需 enigo**；enigo 仅在需要合成测试输入时备选。
   - ADB：通过 `maa-framework-rs` 的 Adb Controller（内部已封装），或 `tokio::process` 调 `adb` 命令行。

### 2.2 可行性结论

**完全可行，且是本项目的最优路线**：官方绑定 + 已被验证的 Tauri/vue-flow 组合，避免 C++/Python 双语言维护成本。

### 2.3 与原方案对比

| 维度 | 原方案（C++ FFI / Python） | Rust 方案（本文） |
| ------ | -------------------------- | ------------------ |
| Maa 集成 | 手写 bindgen 或 pymaafw | 官方 `maa-framework-rs` |
| GUI | Qt / PySide6 | Tauri2 + Vue3+VueFlow（同 MaaInspector） |
| 录制 | 各语言独立实现 | `scrap`+`inputbot`+`enigo` 统一后端 |
| 产物体积 | 较大 | Tauri 体积小（~15MB） |
| 跨平台 | 需分别处理 | Tauri 一次构建多端 |

### 2.4 MaaFramework 官方 GUI / 集成推荐 与本项目选型

**官方事实上的推荐 GUI：MFAAvalonia**

- 仓库 `github.com/MaaXYZ/MFAAvalonia`，位于 MaaFramework 同一官方组织 `MaaXYZ`，是 README「通用 UI」列表首位。
- 基于 **Avalonia UI + SukiUI**（C#/.NET），通过 **Project Interface V2 协议**描述任务/选项/控制器/界面文本，用户即可配置并运行。
- 定位为「通用 GUI 外壳」，本身不含业务资源，需与基于 MaaFramework 的资源项目集成。

**更本质的官方推荐（集成模式）**

- **集成方案 2（JSON + 插件扩展 / AgentServer 子进程）** 是官方推荐的开发方式：保留 JSON 流水线低代码优势，复杂识别/动作逻辑托管到 AgentServer 子进程，打破语言壁垒，且完美兼容生态可视化工具。
- **Project Interface V2 协议** 是 GUI 与资源解耦的标准：定义 PI 后，任意衍生 GUI（MFAAvalonia、MXU、MWU 等）都能驱动你的资源包。

**本项目选型（关键决策）**

- GUI 外壳保持 **Rust + Tauri 2 + Vue3 + Vue Flow**（沿用既有决策，与 MaaInspector 同栈）。
- 不直接套用 MFAAvalonia（C#），但采纳官方推荐的两项「标准」：
  1. **遵循 Project Interface V2 协议**：MaaWizard 产出的资源包附带 `interface.json`（PI V2），因此**既能被本工具运行，也能被 MFAAvalonia 等官方 GUI 直接加载**——纳入官方生态而非另起炉灶。
  2. **采用集成方案 2 运行时模型**：pipeline 以 JSON 表达；复杂逻辑通过 `Custom` 节点 + AgentServer（Python 子进程）扩展，保持与生态工具兼容。
- MFAAvalonia 作为**参考实现与兼容目标**：其 PI V2 交互设计、选项接线方式供借鉴；双方资源包双向互通。

> 取舍说明：若未来决定放弃 Rust、直接基于 MFAAvalonia（C#/Avalonia）构建，可最大化官方生态对齐，但违背既有 Rust 决策；当前以「保留 Rust + 采用官方协议」为最优折中。

## 3. 系统架构

```text
┌─────────────────────────────────────────────┐
│  UI 层 (Vue3 + Vue Flow, WebView)            │
│  · 节点图编辑器  · 录制面板  · 设备/调试面板  │
└───────────────┬─────────────────────────────┘
                │ Tauri IPC (commands / events)
┌───────────────▼─────────────────────────────┐
│  应用层 (Rust / Tauri commands)              │
│  · pipeline 服务(加载/保存/校验)             │
│  · 录制引擎(坐标/智能)                       │
│  · 设备管理器(ADB/Win32 连接)               │
│  · 调试事件总线(Tasker focus → UI 高亮)      │
└───────────────┬─────────────────────────────┘
                │ 调用
┌───────────────▼─────────────────────────────┐
│  领域层 (maa-framework-rs)                    │
│  · Resource(加载资源包)                       │
│  · Controller(Adb / Win32)                    │
│  · Tasker(调度执行 / 节点状态回调)            │
└───────────────┬─────────────────────────────┘
                │ 设备通信
┌───────────────▼─────────────────────────────┐
│  设备层 (Android ADB / Windows Win32)         │
└─────────────────────────────────────────────┘
```

## 4. 模块设计

| 模块 | 职责 | 关键 Rust 依赖 |
| ------ | ------ | --------------- |
| **M0 Maa 运行时封装** | 加载 `MaaFramework.dll`，封装 Resource/Controller/Tasker 生命周期 | `maa-framework` |
| **M1 图编辑器** | Vue Flow 渲染 `next`/`on_error` 有向边与节点属性面板；复用 MaaInspector 节点组件 | `vue-flow`（前端） |
| **M2 录制引擎** | 坐标模式：监听键鼠事件生成 Click/InputText/Swipe 节点；智能模式：每步截图 + ROI 框选生成 OCR/TemplateMatch 节点 | `inputbot`, `scrap`（执行由 MaaFramework Controller 负责，`enigo` 非必需） |
| **M3 模板抓取器** | 截图框选区域 → 导出图片 → 生成 TemplateMatch 节点；可选自动 OCR 命中文字 | `scrap`, `image` |
| **M4 设备管理** | ADB/Win32 设备发现与连接，参数按控制器类型校验 | `maa-framework` Controller |
| **M5 调试与状态回显** | Tasker `focus` 回调经 Tauri Event 推送到前端实时高亮当前节点 | `tauri::Event` |
| **M6 AI 增强** | 自然语言生成 pipeline；可子进程调用 `maafw-cli` / `maa-mcp`，或直连 LLM API | `tokio::process`, `reqwest` |

## 5. 数据模型

- **Pipeline 双模式序列化**：兼容 V1（平铺字段）与 V2（`recognition:{type,param}` / `action:{type,param}`），Rust 侧用 `serde` 定义枚举结构并在读写时互转。
- **资源包约定**：`pipeline/` 目录 + `default_pipeline.json`；忽略 `.`/`$` 前缀（由 `maa-framework-rs` 自动处理，封装层仅做结构校验）。
- **录制产物**：录制引擎输出中间 AST → 序列化为 Pipeline JSON → 经 M0 加载运行。

## 6. 分阶段路线图（Rust 实现视角）

### 阶段 0 —— 运行链路打通（最小可验证闭环）

- 用 `cargo tauri init`（或 `create-tauri-app`）搭建 Tauri2 + Vue3 骨架。
- Rust 侧引入 `maa-framework`，`load_library` 加载预编译库。
- 实现：加载一个示例 resource 包 → 连接 Controller（先 Win32）→ `Tasker::post_task` 运行并打印结果。
- 交付物：能跑通一个 Maa 任务的最小桌面程序。

### 阶段 1 —— 图编辑器

- 前端引入 Vue Flow，复用 MaaInspector 的节点/连线组件。
- Tauri commands：`load_pipeline(path)` / `save_pipeline(json)`（基于 `serde_json`）。
- 支持 V1/V2 导入导出、节点属性动态表单（按 recognition/action 类型渲染参数控件）。
- 交付物：可导入/导出/可视化编辑 Pipeline 的编辑器。

### 阶段 2 —— 坐标录制 MVP

- Rust 录制引擎：`inputbot` 监听全局键鼠，`scrap` 周期性截屏；生成 Click/InputText/Swipe 节点。
- 前端「开始录制 / 停止 / 预览」面板，录制结果直接落入图编辑器。
- 交付物：录屏即生成可运行流程（按键精灵式体验）。

### 阶段 3 —— 智能识别录制

- 每步操作后自动截图；用户框选 ROI → `M3 模板抓取器` 生成 TemplateMatch/OCR 节点。
- 可选：对点击位置的文字自动 OCR，生成 `expected` 匹配。
- 交付物：抗分辨率/位置变化的识别型流程。

### 阶段 4 —— 设备管理与调试

- 设备管理 UI：ADB 设备发现/连接、Win32 窗口列表选择。
- `M5`：Tasker `focus` 回调经 Tauri Event 实时高亮当前执行节点。
- 交付物：双端一键运行 + 实时调试视图。

### 阶段 5 —— AI 增强

- 子进程调用 `maafw-cli` / 启动 `maa-mcp`，或直连 LLM：用自然语言描述意图 → 生成 Pipeline。
- 模板库与分享（导出/导入 resource 包）。
- 交付物：AI 辅助生成 + 社区分享闭环。

## 7. 可复用资产（避免重复造轮子）

- **maa-framework-rs**：官方 Rust 绑定，免去 FFI 手写。
- **MaaInspector**：Tauri + Vue3 + vue-flow 节点编辑器代码（架构同源，可直接借鉴/复用组件）。
- **MaaPipelineEditor**：LocalBridge 调试协议、Pipeline 字段排序思路。
- **MaaFramework 官方 JSON Schema / 文档**：Pipeline V1/V2 协议规范。
- **maafw-cli / MaaMCP**：阶段 5 AI 能力的现成后端，无需自研设备驱动。
- **MFAAvalonia**：官方通用 GUI（C#/Avalonia，MaaXYZ 组织），作为 PI V2 参考实现与兼容目标；其交互设计、选项接线方式可借鉴，本项目产出资源包可与之互通。

## 8. 风险与合规

- **模板门槛**：智能录制 + 模板抓取器降低用户准备模板的成本。
- **反作弊 / 合规**：仅限合法自动化黑盒测试，UI 明确声明禁止外挂与破坏反作弊机制（遵循 MaaFramework LGPL-3.0）。
- **多端控制器差异**：动作参数需按控制器类型（Adb/Win32/MacOS…）校验，`maa-framework-rs` 已封装差异，封装层做合法性提示。
- **Rust 异步**：设备操作、录制循环使用 `tauri::async_runtime`（Tokio），避免阻塞 UI 线程。
